推荐实现

顶部参数栏单独补充 map / request / planner / start/stop 控件；中下部尽量保持与 HTML 同构。

动态数据唯一来源：ReAct/run_access_point_decision.py 产出的 trajectory JSON。

图片区从 map + trajectory 派生：左图展示 map/roi，右图展示部署结果或已有可视化产物。

指标口径固定：表格中的 capacity 只显示容量列名；最终实现里若轨迹同时出现 spectral_efficiency / SE，会与信道容量分开解析，不混用这列。

字段落点

直接可对齐

  • step_logs -> 表格、当前 step、动作链、运行时间
  • traj[0].observations -> 用户需求、结构化目标、候选/状态摘要
  • traj[0].actions + rationales -> 动作链、解释文本
  • perf.final_sites -> 当前站点集合、AP count

需要 GUI 内做轻量转换

  • HTML 的“模型选择 / 方法选择”是展示态，不直接等于 CLI 参数，需要从 planner / eval-model 推导高亮
  • 右上表格的 location 列需要把各 step 的站点集整理成字符串
  • 两张图片区需要补一个稳定的本地图像生成/选择规则
